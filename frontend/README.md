# English Courses Platform — Frontend Клієнт

Клієнтська частина платформи онлайн-курсів та бронювання уроків англійської мови. Додаток реалізовано як сучасний SPA (Single Page Application) без додаткових важких залежностей, що взаємодіє з бекендом Django REST Framework через JWT автентифікацію.

---

## 🚀 Функціонал додатку

### 1. Сторінки та інтерфейс:
- **Головна & Публічний каталог (`#home`)**:
  - Доступний усім відвідувачам без авторизації.
  - Перегляд списку репетиторів з фільтрацією за напрямком (`specialization`) та рівнем англійської (`english_level`: A1–C2, Native).
  - Модальне вікно з детальним профілем викладача (`GET /api/teachers/<id>/`): біографія, ставка за годину, рейтинг, прикріплені курси та список доступних занять (`lessons`).
  - Відображення каталогу курсів платформи.
- **Сторінка реєстрації (`#register`)**:
  - Поля: `username`, `email`, `first_name`, `last_name`, `password`, `password_confirm`, `english_level`.
  - Валідація з підсвічуванням індивідуальних помилок для кожного поля (довжина, формат email, складність пароля, збіг паролів).
  - Автоматичне отримання JWT-токенів та вхід після успішної реєстрації.
- **Сторінка авторизації (`#login`)**:
  - Вхід за допомогою `username` або `email` та пароля.
  - Отримання та збереження `access` і `refresh` токенів у `localStorage`.
- **Особистий кабінет студента (`#dashboard`)**:
  - Доступний **лише авторизованим користувачам**.
  - Перегляд профілю поточного користувача (`GET /api/users/me/`).
  - Перегляд заброньованих занять (`GET /api/users/me/bookings/`).
  - Інтерактивна форма бронювання нового уроку у викладача (`POST /api/bookings/`).
  - Скасування запланованого бронювання (`DELETE /api/bookings/<id>/`).

## 🔒 Поведінка та безпека (JWT Lifecycle)

1. **Захист маршрутів (Route Guards)**:
   - Спроба неавторизованого користувача відкрити Особистий кабінет (`#dashboard`) автоматично перенаправляє його на сторінку входу (`#login`) зі збереженням адреси повернення.
   - Після успішного логіну користувача повертає на ту сторінку, з якої його було перенаправлено.
   - Авторизований користувач не може відкрити сторінки логіну чи реєстрації — його автоматично скеровує до кабінету.
2. **Динамічний хедер**:
   - Неавторизований користувач бачить кнопки **"Увійти"** та **"Зареєструватися"**. Кнопка виходу прихована.
   - Авторизований користувач бачить бейдж зі своїм ім'ям (наприклад, `👤 Владислава (student)`) та кнопку **"Вийти"**. Кнопки входу приховані.
3. **Автоматичне оновлення токенів (Silent Token Refresh)**:
   - Обгортка `apiRequest` перехоплює відповіді зі статусом `401 Unauthorized`.
   - За допомогою збереженого `refresh` токена відправляється запит на `POST /api/users/token/refresh/`.
   - Новий `access` токен зберігається, а попередній запит виконується повторно без участі користувача.
4. **Logout**:
   - При виході з акаунта викликається бекенд-ендпоінт `POST /api/users/logout/` (токен додається до чорного списку), після чого клієнт повністю видаляє збережені токени та повертається на головну сторінку.

## 🛠 Інструкція із запуску фронтенду

### 1. Передумови
Переконайтеся, що бекенд-сервер запущений на адресі `http://127.0.0.1:8000`:
```bash
python manage.py runserver 127.0.0.1:8000
```

### 2. Запуск фронтенду

#### Варіант А: Через вбудований HTTP-сервер Python (Рекомендовано)
У папці `frontend/` виконайте:
```bash
# Якщо перебуваєте в корені проєкту:
python -m http.server 3000 --directory frontend

# Або перейдіть у папку:
cd frontend
python -m http.server 3000
```
Відкрийте у браузері: [http://localhost:3000](http://localhost:3000).

#### Варіант Б: Через розширення VS Code Live Server
1. Відкрийте папку `frontend` у VS Code.
2. Клацніть правою кнопкою миші на `index.html` -> **"Open with Live Server"**.

#### Варіант В: Через npx serve
```bash
npx serve frontend -p 3000
```
